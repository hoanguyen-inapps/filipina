 1. SOURCE CODE / INTELLECTUAL PROPERTY / ACCOUNT
 OWNERSHIP

 Ownership and control of the product is a requirement of this engagement.

 FilipinaConnect.US will own all project-specific work product created specifically for the project, including, but not
 limited to:

    Source code and object code
    Database schemas

    APIs and integrations developed specifically for FilipinaConnect.US
    UI/UX designs and project-specific design assets

    Documentation
    Test automation

    Configuration
    Infrastructure-as-code

    Project-specific scripts and tooling
    Other project-specific work product

 Repository Ownership

 All source code must be maintained throughout development in a GitHub organization/repository owned and
 controlled by FilipinaConnect.US.

 FilipinaConnect.US must have full administrator access and current credentials to all repositories at all times. The
 development company may be provided appropriate access to perform its work but may not be the sole owner,
 administrator, or custodian of any source-code repository.

 Production and Business Account Ownership

 Where provider rules permit, FilipinaConnect.US will own and control its:

    Production hosting/cloud accounts
    Domains and domain-management accounts

    Apple Developer account
    Google Play Developer account

    Payment-processing accounts
    Third-party service accounts

    API credentials
    Databases

    Production data
    Other critical production systems and services

 FilipinaConnect.US must have current administrative credentials and appropriate access to these systems throughout
 the engagement, rather than receiving access only at project completion. The development company must not maintain
 exclusive control over any critical system required to operate the FilipinaConnect.US platform.

 Pre-Existing Technology

 The developer must disclose any pre-existing proprietary technology, frameworks, libraries, or third-party
 components that will be incorporated into the solution.

 FilipinaConnect.US must receive all rights necessary to operate, modify, maintain, access and control project data,
 transfer the application to another development provider, and continue development with another development provider.

 The completed platform must not contain an undisclosed dependency that prevents FilipinaConnect.US from
 independently operating or transferring the product.

 2. OPEN-SOURCE / THIRD-PARTY SOFTWARE

 The developer must take reasonable steps to protect FilipinaConnect.US from licensing restrictions that could affect its
 proprietary software or future commercialization.

 The developer may not incorporate software subject to GPL, AGPL, SSPL, or other reciprocal, network-copyleft, or
 similarly restrictive licensing terms that could require disclosure, licensing, or distribution of FilipinaConnect.US
 proprietary source code without prior written approval from FilipinaConnect.US.

 The developer must disclose all material third-party and open-source components incorporated into the project.

 At final delivery, the developer must provide a complete software dependency and license inventory, identifying
 material third-party and open-source components used in the application and their applicable licenses.

 Any proposed use of software that could impose material licensing obligations on FilipinaConnect.US must be disclosed
 and approved in writing before implementation.

 3. PROJECT MILESTONES / DELIVERABLES / ACCEPTANCE /
 PAYMENTS

 Because this is expected to be a fixed-price development engagement, project payments should be tied to clearly
 defined milestones, deliverables, and acceptance criteria rather than simply the passage of time.

 Developer Proposal Requirements

 The developer's proposal must identify:

    Each development milestone
    Specific deliverables associated with each milestone

    Target completion date
    Acceptance criteria

    Payment amount or percentage associated with the milestone
    Dependencies or assumptions

    What constitutes completion and acceptance

 Suggested Milestone Structure

 Developers may recommend a different milestone structure if justified, but the proposal should address at minimum the
 following major phases:

 MILESTONE 1 — ARCHITECTURE & DESIGN

 Technical architecture; system design; UI/UX/design deliverables; database architecture; integration strategy;
 development environment/repository setup.

 MILESTONE 2 — CORE BACKEND & INTEGRATIONS

 Core application infrastructure; database implementation; SmartMatchApp/API integration, as applicable; required
 third-party integrations; authentication/security foundation; other core backend functionality.

 MILESTONE 3 — MOBILE & WEB BETA

 Functional iOS application; functional Android application; web application; core user workflows; messaging and other
 applicable platform functionality; internal beta release.

 MILESTONE 4 — UAT / PRODUCTION READINESS

 User Acceptance Testing (UAT); bug resolution; security and performance testing; app-store submission readiness;
 production configuration; documentation; final integration testing.

 MILESTONE 5 — PRODUCTION LAUNCH & HANDOVER

 Production deployment; application launch; final acceptance testing; current source repositories; complete credentials and
 account access; technical documentation; system/configuration documentation; final project handover.

 Acceptance-Based Payment

 Payment should be made after the applicable milestone has been completed and accepted, rather than solely
 because a scheduled date has been reached. Acceptance criteria should be agreed upon in advance for each milestone.

 FilipinaConnect.US should retain at least 10–15% of the total contract value as the final payment.

 The final payment should become due only after:

    The application is live in production;
    Final acceptance testing has been successfully completed;

    All source-code repositories are current;
    All required repository and production credentials have been provided;

    Required technical and operational documentation has been delivered;
    All applicable accounts and systems are fully transferred or under FilipinaConnect.US control; and

    The agreed project deliverables have been completed and accepted.

 Developers should clearly identify their proposed milestone payment schedule in their proposal.

 4. CHANGE ORDERS / OUT-OF-SCOPE WORK

 The agreed Project Brief and this Addendum establish the baseline scope of the engagement.

 Any work requested by FilipinaConnect.US or proposed by the developer that is outside the agreed scope must be
 addressed through a written change order before the additional work begins.

 A change order should clearly identify:

    Description of the requested change

    Reason for the change

    Additional cost, if any

    Schedule impact, if any

 DEVELOPER ACKNOWLEDGMENT

 Developers responding to the FilipinaConnect.US Project Brief should review this Addendum together with the original
 Project Brief.

 The developer's proposal should clearly identify:

    Acceptance of these requirements;

    Any specific exceptions or requested modifications;
    Any technical limitations affecting implementation;

    Any third-party licensing or ownership issues;
    Proposed milestone structure and payment schedule; and

    Any assumptions that could materially affect cost, schedule, ownership, or project delivery.

 Silence or omission should not be interpreted as acceptance of an exception. Any requested deviation from these
 requirements should be specifically identified in the developer's proposal.
